# 데이터 백업

이 문서는 라이브러리, 업로드 원본, 사용자 포즈, 검색 캐시를 복사해 두는 방법입니다. 백업은 원본을 옮기지 않고 복사만 합니다. 운영 중인 `data`와 `storage` 폴더를 백업으로 덮어쓰는 기능은 없습니다.

## 백업 실행

프로젝트 폴더에서 다음 명령을 실행합니다.

```powershell
npm run backup:data
```

성공하면 `backups/costume-data-날짜-시각` 폴더가 생깁니다. 이름은 한국 표준시 기준이며, 같은 이름의 백업이 있으면 만들지 않고 중단합니다. 이전 백업은 지우거나 덮어쓰지 않습니다.

## 저장 위치

백업은 프로젝트 안의 `backups` 폴더에 있습니다. 예:

```text
backups/costume-data-20260929-203845/
```

## 포함되는 데이터

- `data/library.json` — 라이브러리 목록
- `data/library-folders.json` — 폴더와 소속
- `data/library-annotations.json` — 메모와 태그
- `data/pose-presets.json` — 사용자가 저장한 포즈
- `data/search-runtime.json` — 검색 캐시와 이번 달 호출 횟수
- `storage/library/uploads/` — 직접 업로드한 원본 파일

검색 캐시에 들어 있는 이미지 주소는 외부 사이트의 URL입니다. 그 이미지 파일 자체는 백업에 들어 있지 않습니다. 이 컴퓨터에 저장된 원본은 업로드 파일뿐입니다.

기본 포즈 프리셋은 프로그램에 포함되어 있어 백업하지 않습니다. 브라우저에만 있는 마지막 검색 화면은 백업하지 않습니다.

## 제외되는 항목

- `node_modules`
- `.next`와 그 밖의 빌드 결과
- 임시 파일과 로그
- `.env`, `.env.local`
- API 키와 인증 토큰

API 키는 백업에 넣지 않습니다. 프로그램을 다른 곳에 둘 때는 키를 백업과 따로 보관해야 합니다.

## 무결성 확인

백업 폴더의 `manifest.json`에는 만든 시각, 파일 목록, 크기, SHA-256 해시가 있습니다. `manifest.sha256`은 그 목록 파일의 해시입니다.

```powershell
npm run backup:verify -- backups/costume-data-날짜-시각
```

목록이 바뀌었거나 파일 내용이 해시와 다르면 확인은 실패합니다.

## 격리된 복원 테스트

복원은 비어 있는 다른 폴더에만 합니다. `data`와 `storage`에는 복원하지 않습니다.

```powershell
npm run backup:restore -- --backup backups/costume-data-날짜-시각 --target C:\temp\costume-restore-test
```

대상 폴더에 파일이 이미 있으면 복원을 시작하지 않습니다. 목록, 해시, 경로 검증에 실패하면 파일을 남기지 않습니다. 상위 폴더로 나가는 경로와 절대 경로는 거부합니다.

## 운영 데이터 복원 시 주의

이 단계의 복원 명령은 지금 쓰는 라이브러리와 검색 캐시를 바꾸지 않습니다. 운영 데이터를 백업 내용으로 바꾸는 작업은 제공하지 않습니다. 그렇게 하려면 프로그램을 멈춘 뒤, 현재 `data`와 `storage/library/uploads`를 따로 보관한 다음 사람이 파일을 교체해야 합니다. 교체 전에 `npm run backup:verify`로 백업이 온전한지 확인하세요.
